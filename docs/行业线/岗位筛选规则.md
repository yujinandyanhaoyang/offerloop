# 行业、公司与岗位筛选

本文件保存通用方法。地区、岗位倾向、薪酬底线、可接受用工形式等从个人档案读取，不能继承维护者的选择。先明确当前决策问题，以真实需求和个人可进入机会形成主投、并行验证、暂缓三类结论。

需要判断行业前景、选择查询渠道或读取报告时，先用 [行业研究方法](行业研究方法.md)。公共研究能力与个人选择分开维护。

## 从支付需求到个人机会

按“付款人和预算 → 细分需求 → 产业集群 → 企业价值位置 → 目标团队 → 岗位准入与回报”逐层检查。行业增长、公司赚钱、个人获得回报分别验证，不能相互替代。

- 行业上行要看可比需求、采购、交付和回款。融资、政策口号、产能规划、单家公司增长均不足以证明。
- 技术进步可能降低实现成本，也可能扩大需求。判断谁掌握客户、分发、合法数据、资源、认证与可靠交付；不以“AI 能写代码”推定所有技术或行业壁垒消失。
- 集群看客户、供应链、研发制造、服务与人才实际共址，以及多个独立雇主的可进入岗位。注册地、园区名录与实际工作地分开。
- 财富与职业选择同时比较可兑现现金、工时迁居成本、可迁移能力、可合法积累的成果和未来替代雇主。未兑现股权单列，不编收益率或成功概率。
- 不因岗位热门、模型新颖或语言熟悉就选方向。比较独立雇主需求、本人已有证据、最短可验证缺口及相邻岗位覆盖范围。

## 公司与岗位检查

| ID | 问题 | 适用证据 |
| --- | --- | --- |
| C1 | 生态位及竞争优势 | 比较范围明确的份额、采购、切换成本、关键资源和技术；不强求每个用户只投龙头 |

| C5 | 目标团队有何资源 | 产品线、人员、职责、预算与评价方式，内部未知留面试核实 |
| J1 | 实际负责什么 | 可交付的业务、工程、质量或运营结果 |
| J2 | 能积累什么 | 能独立说明且市场认可的能力和成果 |
| J3 | 责任与资源是否匹配 | 指导、协作、工具权限、评价方式 |

## 准入与真实 JD

逐岗保留原链接、岗位 ID、主体/团队、工作地、招聘渠道、发布日期或未知、核对日期及状态。页面存在、按钮可点、HC 已确认和本人符合条件是四种不同状态。默认查近三个月；历史岗位单列，不能算当前可投。

学历、专业、经验、毕业窗口、正式就业和社保要求按公告分别核实。应届补招、下一届校招、近年毕业生岗位、初级社招分开。公务员、事业单位、国央企、军工各按具体招录公告与岗位表，不给统一“应届身份”。政策、企业招聘和地方补贴口径分开；未写明标“待招聘方确认”，由用户决定是否联系。实习不得加进正式年限，既不能假设无就业，也不能因有社保自动排除全部校招。

技术岗逐条保存“原 JD 栏目/原词｜要求强度｜必需/任选/示例/加分｜个人证据与缺口”。非技术岗同样提取工作成果、资质、语言和行业经验。未指定的条件不补成雇主要求。

技能状态区分看过、使用过、独立实现、交付、实测改善。少数样本不足以推定市场份额；统计去重岗位及独立雇主，写覆盖限制。未知不按零能力，也不按简历自述当已验证。

技术原词与归一标签同时保留。语言、运行时、框架、协议、存储、部署、Agent 机制与系统经验分开；Docker 和 Kubernetes、MCP 和 Tool Calling 不能归并后抹掉差异。“任选一门”“例如”“优先”不能改成全部必需。技术建议另列，不补写原 JD 未指定的要求。

跨岗比较采用“企业需要的结果｜支持岗位与独立雇主｜要求强度与选择关系｜本人证据/未知｜差距类型｜最小证明成果｜优先级”。差距分表达、证明、能力和硬门槛。将学习落到真实模块及验收，例如恢复机制如何由状态和回执验证；不把所有 JD 技术并集变成必学清单。

招聘紧迫性只影响排序：未知、招聘方明确说急招、已核名额及到岗/面试节点分别记录，不能把“急招”文案当真实 HC，也不因缺少急招证据排除合适机会。硬条件和用户明确底线不由加权总分抵消。

## 职业回报与投入边界

比较当前基线和少量真实替代机会，分别回答“进得去、做得对、回报值得”。固定收入、浮动奖金、佣金、未兑现股权分列，注明税前税后及兑现条件；收入不等于可积累现金。迁居、生活与实际工作成本单列，可回收押金不能当消费，也不能把额度当储蓄。

比较工时、待命、通勤及可持续投入，不将所有休息时间折价，也不假设用户能额外承担第二份全职工作。有需要时用同口径固定年收入和实际工时作辅助比较，不能代替成长或合同判断。用真实现金和支出评估无收入承受能力，不编成功概率。

可迁移能力须落到本人能解释、修改和复现的成果，并验证后续雇主是否需要。成长承诺不能无限抵消低回报。每条候选注明付款原因、能力迁移、进入成本、主要失败原因及最小验证动作；缺少实际容量时不设置投递配额或学习工时。

## 输出与改判

给出一个条件性首选、并行路线和暂缓理由，说明已有证据、最影响面试的缺口、值得近期补的项目及改判条件。材料准备和真实投递反馈可以并行，不等全栈学完。

单岗结论为 shortlist / clarify / exclude。关键事实未知时明确最小补证，不为缺内部预算等后期信息无限阻塞初筛。资格拒绝、无回复、技术面反馈分别回写，只有新证据改变判断才重开研究。一次性摘录提炼后清理，现行判断只更新 memory/workspace.json，操作状态保存在投递台账；README 不维护第二份方向。
