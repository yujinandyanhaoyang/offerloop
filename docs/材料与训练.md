# 材料与训练

内容线和笔面线共享个人档案与已核原 JD，各自维护在用产物。默认本地工作。

## 简历与项目

先按职责和门槛映射个人证据，再改表达。经历用“实际问题 → 本人责任 → 实施与取舍 → 验收 → 已证实结果”组织。结果没有指标时写可核的功能、采用范围和限制，不编百分比或工时。实习和正式工作分列，年月保持一致。

项目说明应覆盖输入、完整处理链、人工介入、失败处理、恢复和验收。技术组件只有实际存在且能解释才写；AI 辅助、复用框架不否定整体工程责任，也不等于亲自实现了依赖库。数字、采用和改善需要已有证据，公司原始数据、密钥和客户资料不得进入求职材料。

按岗位族维护少量当前简历版本，共用同一事实源。只为目标差异调整项目优先级与能力表达，不为每次投递复制全文。参考简历提炼写作规律，不能抄别人的经历。原件与必要转换件分开，一种可读表示足够时不重复保存 HTML/PDF/Markdown。

项目改造先核已有实现，再选择同时补目标岗位缺口、解决真实问题且能验收的增量。不堆技术栈，不把计划写成成果。对无项目或非技术用户，用课程、实习、作品、业务案例等真实经历证明相应能力。

项目卡是共同事实底稿：问题与服务对象、原状态及代价、本人责任与协作边界、关键取舍、实现与验收阶段、采用主体与范围、结果依据、未知与下一补证。个人配置、本人开发、AI 辅助及平台提供分别写清。同一卡片供简历、口述与汇报取材，工作经历和项目经历不重复计成果。

交付、接入、采用、效果验证分开。说明谁用来完成什么任务、能否独立和重复使用、仍需多少介入；个人采用也有价值，不强行包装成团队推广。评价先定任务目标、合格判据、样本和评价人；调试样本、独立验证及线上效果分列，保留失败与人工复核成本。单例修复不等于共性问题已解决。

数字固定期间、单位、分子分母和去重键，任务、case、attempt、根因、日志不能混加。采集成功、执行成功、业务通过、判断正确和任务验收分别计量，空干预字段不能证明无人介入。无完整分母就报可复算范围；无同口径基线不报净节省，不将某个样本外推为累计效果。

改简历前定点核对上次版本以来会改变正文的事实，保留出处和适用边界，不机械放大旧数字。先直接回答“做了什么、本人做哪部分、结果如何”，再按追问展开技术；不知道就标明。评审批注与外发稿分开，待处理批注不能作为已消费转换件删除。

## 本地笔面

优先用户真实邀约和目标岗位近期待考内容。面经保留原帖、时间、招聘身份、轮次和问题，识别推广和转载；校招、社招、历史参考分别标注。无真实题源时可用模拟题，但必须明确模拟。

一次一题，先让用户脱稿回答，再记录原话、指出关键缺口并给能口述的参考答案。不能把参考答案当用户已掌握，不能在招聘方要求独立作答的实时考核中代答。复验采用异题或异例，并记录通过依据。

本地记录使用 [interview-drill](../skills/interview-drill/SKILL.md) 与 scripts/interview_drill.py。题源归笔面线，不放行业线。训练原文留本地，飞书只按需同步进度、主要缺口和下一动作。

面经区分面试发生、首次发布、编辑和读取日期，不能用抓取时间或月日推定年份。原帖核身份、轮次、题面与亲历陈述；同作者同流程多轮及转载去重，校招或其他团队只作相邻参考。导流、无来源拼题和泛感想不作主要题源，但不能仅凭文风断言 AI 生成。作者猜测的拒绝原因不改写成企业结论。

脚本校验日期、链接、去重与结构；逐篇语义审查由助手完成。题目转为“考什么、哪项本人经历可回答、还缺什么”，不补造原题和追问，不把参考答案当本人实践。已有题源优先定点增量，达到本轮需求即停止，不为数量扩搜。

资源选择看实际机制、地区渠道、维护成本和许可。说明、源码存在、运行通过与真实求职效果分开；读过外部项目不代表完成集成。只有现有工作出现真实瓶颈才引入工具，研究和开发不能挤占已经可以开始的求职验证。

## 反馈如何改方向

| 观察 | 能支持的判断 | 下一步 |
| --- | --- | --- |
| 明确资格拒绝 | 对应岗位/渠道的条件不符 | 核公告及原拒绝理由，调整资格范围 |
| 简历无回复 | 结果未知，可能有渠道、材料、时机等原因 | 比较同岗位族样本和等待窗口，检查简历首屏证据 |
| 技术面明确缺口 | 某题或能力尚未证明 | 归入具体实现/原理/表达问题，小步练习后异题复验 |
| 面试或 offer | 该次招聘的真实反馈 | 核职责、回报与准入，不扩推全市场适配 |

采用 APP-ID 关联 JD、简历版本、回执、面试题和下一动作。只有真实回执才记已投或邀约，学习完成不等于面试通过。更新现行方法和状态后清理一次性分析，保留仍用于训练和防重的原始记录。
