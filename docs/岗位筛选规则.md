# AI时代公司与岗位过滤器

版本：2026-11-03-v6。新增「不允许」护城河检查与「外包／驻场服务商」强筛一票否决。适用于跨行业求职；行业方向线（见个人项目 规则\行业方向线.md）维护研究范围与分工，本篇统一维护筛选条件，投递线直接引用。目标是离开当前不合适的工作环境，进入AI时代有真实客户、持续市场、可防守价值位置和赚钱能力的行业龙头或细分龙头，在有资源的岗位获得可兑现回报与成长。公司领先不自动代表目标团队、岗位或工作强度合适。

## 先找钱从哪里来，再找本人能进入的位置

**客户需求与预算 → 上行的细分市场 → 产业集群 → 龙头的核心业务与团队 → 本人可进入的岗位 → 面试与offer核验。** 行业判断看需求和产业结构；公司判断看价值获取和经营质量；岗位判断看本人职责、准入与回报。政策、营收、产量、融资、品牌和AI标签均不能单独放行。

按本人择业取舍，传统SaaS仍为核心、AI仅附加或包装的公司排除；不因使用API、开源模型、订阅计费或公司名称含“软件”就认定套壳。核心业务不清保留待核。也不把所有软件必然消失或传统行业天然稳定作为事实。

开发、Python、Agent和自动化是进入行业的工具，岗位可包括产品／系统验证、应用工程、质量可靠性、设备／运行数据和技术型供应链运营。研究阶段暂不按年限排除，实际专业、身份、技能、资质及招聘方是否接受必须如实判断。城市偏好、可接受收入、工时与迁居沿本人最新确认，不从旧简历期望字段推定底线。

## 行业与产业集群

| 检查 | 进入下一步的依据 | 必须避免 |
|---|---|---|
| 行业增量 | 真实付款人和需求；政策落实为采购、投资或应用；同口径需求与竞争证据支持具体细分市场扩张 | 仅有政策口号、规划产能、单家公司增长或营收口径变化 |
| AI时代价值 | AI更便宜后，该产品、设备、运行或服务仍被需要；公司可凭客户关系、关键技术、合法专有数据、可靠交付或基础设施获得回报 | 只凭概念推断防御力；将“使用AI”或“有物理设备”当充分证明 |
| 产业集群 | 客户、供应链、研发／制造、服务与人才实际共址；存在多个可替代雇主及本人可进入的岗位 | 产业园名录当真实业务密度；注册地当工作地；全国龙头当本地团队强 |
| 个人落点 | 对目标岗位族开放的有效招聘、准入差距、通勤迁居成本和替代机会可比较 | 用城市总产值或全行业职位数代替本人机会；未去重样本冒充岗位密度 |

集群先用已有证据形成搜索范围，再用去重的企业和原JD检验。样本注明来源、日期、数量和覆盖限制，不为了“产业集群”标签强行限制岗位在园区内。资料默认查当日向前三个月；数据期另标，缺近期证据时针对该问题追溯历史。

## 公司五项检查

| ID | 核心问题 | 有价值的证据 |
|---|---|---|
| C1 生态位与领先地位 | 在哪个产品、客户群和地域领先？AI或上游平台增强后，其价值会被替代、被抽走还是增强？ | 同市场可比份额／排名、重复采购、关键客户采用、装机与服务网络、标准或关键技术；注明分母和范围，品牌自称不算确认 |
| C2 客户与真实需求 | 谁持续付钱，需求能否延续？ | 采购／中标、客户侧采用、复购、交付运行、订单；免费试点与合同、收入、回款分别记录 |
| C3 增长真实性 | 增量来自销量、价格、新客户、并购还是会计／分类变化？ | 可比期间和业务口径；行业增量与公司夺份额分开，收入下降不能自动归因AI |
| C4 赚钱与现金 | 扣除研发、获客、交付、售后、资本投入后能否留住合理收益？ | 主业利润质量、经营现金、回款和债务压力，按业务模式看适用指标；集团盈利不代替目标业务质量 |
| C5 团队与价值分配 | 目标业务是否获资源，岗位能否参与创造并分享收益？ | 真实岗位、产品线与职责、团队投入；招聘沟通补HC、预算、人员流动及评价方式 |

**龙头优先落实到可核实的细分市场地位。** 有客户或上市不等于龙头；集团名气不能掩盖边缘业务、外包劳动主体或长期救火团队。首次发现可记“领先地位待核”，主推名单须有适用的领先证据和无明显反证的赚钱逻辑。尚未盈利的企业不能包装成已证实赚钱的目标，仅保留观察理由；不要求所有企业公开内部成本和商业机密。

## 「不允许」护城河检查（国央军与政策强相关主体适用）

适用：央企／国企／军工及背后有国家力量支撑的单位；纯市场化主体不强套此维度。核心命题：这类主体的护城河是「分配规则制定权 + 分配通道占有权」的统一体，不是互联网的资本／技术／生态。它保护「企业存续」，不直接兑现「个人溢价」；垄断越硬的单位，IT 越边缘（成本中心+外包）。牌照（L1 门槛）与数据（L3 产权）只是其中两片。

| 层 | 内容 | 落在企业的可核信号 |
|---|---|---|
| L1 规则层 | 标准／目录／名录／资质（谁定义游戏规则） | 国标／行标／团体标准起草单位；信创目录／军品承制名录／供应商白名单 |
| L2 通道层 | 结算／定价／平台枢纽（谁收过路费） | 电力／数据／碳交易、支付清算、算力调度等平台方 |
| L3 资源层 | 数据／算力／频谱／碳／矿业权（谁占新要素产权） | 数据交易牌照、算力枢纽、绿证／碳配额、频谱／轨道、矿业权 |
| L4 信任层 | 安全测评／涉密资质／身份征信／等保（谁做背书） | 等保／密评／涉密资质、身份库／征信库、信创认证、AI／大模型评测资质 |
| L5 兜底层 | 国家信用／财政承接／编制身份（谁不会死） | 专项债／大基金／政策性资金承接、国家级实验室立项、编制／户口／年金 |
| L6 AI新增 | 评测权／认证权（谁判定 AI／Agent 合格／安全／合规） | 大模型安全合规测评、Agent 可靠性评测、AI 生成内容审核、信创+AI 适配认证；标准未定、名录未编、持证机构未满，是未瓜分完的新「不允许」 |

五年规划判据：该主体是否在「十五五」主推方向（科技自立自强、新型能源体系、数字经济与数据要素、产业链供应链安全、商业航天／低空／量子／生物制造）被规划文本点名，或承接相应财政／专项任务。点名=纳入国家意志的资源配置，优先顺位高；但被点名而落在边缘业务／外包主体的，不因此放行。

优先 vs 排除：
- 优先：母公司护城河为「数据／流程型」（电网／石油／银行／政务），且数科子公司真自研核心系统（有数据独占），且目标岗位落在 L6／L3（AI／Agent 评测、数据场景自研）。
- 排除：母公司纯「牌照／特许型」且无数据价值（烟草／水务／铁路客运）；或「集成／外包管理」壳（JD 全是交付／供应商管理／驻场，无自研、无数据独占）。

对测试开发／AI 测试背景的应聘者：最可进入的是 L6 评测权／认证权 + L3 数据场景层的交叉处——「AI／Agent 评测与质量保障」类新「信任背书」岗位；接口自动化=工具调用编排、CI=Agent 流水线、缺陷闭环=反馈回路，是评测刚需。L1／L2／L5 多为继承性位置，测试开发直接进入难，仅用于判断单位护城河强弱。

## 外包／驻场服务商：强筛一票否决（2026-11-03）

先看有没有真护城河：外包/驻场服务商在 L1–L6 六层全部缺位（无规则权、无结算通道、无数据产权、无信任背书、无兜底），本质是无护城河；用工多为派遣/驻场/项目制，待遇与成长差。**命中即排除，不进候选池，不因「有个测试岗」放行。**

判定信号（任一强信号且无自研反证即排除）：
- 主体名/业务含「人力资源」「信息技术服务」「软件服务」「BPO」，或招聘方是人力资源公司；
- JD 写「驻场/外派/客户现场/项目制/人力外包」，或职责=供应商管理/交付协调；
- 劳动合同主体与用工单位分离；同工不同酬、派遣转正通道窄；
- 主业是 IT 外包/系统集成/实施，无自研核心产品、无独家数据或结算权。

例外（可另议，仍按 J1–J5 核）：外包服务商内部明确挂「自研产品团队」的岗位，需有自研产品、核心代码、数据独占证据；集团自有数科公司（自己人）与外部服务商（供应商）不能混。

边界：挂靠央企集团的外包供应商 ≠ 央企。命中本条时，排除理由固定写「外包/驻场、无护城河」，不再消耗 shortlist 名额。

## 岗位五项检查

| ID | 核心问题 | 不合适的信号 |
|---|---|---|
| J1 业务责任 | 能负责哪项真实产品、工程、质量或运营结果？ | 只有头衔、机械执行、无改进权限、工作与名义战略脱节 |
| J2 可迁移积累 | 一年后能带走什么市场认可的能力与成果？ | 重复改Prompt、长期救火、工作被压缩却无职责升级和积累 |
| J3 资源与组织 | 谁指导、谁配合、资源和评价标准是什么？ | 低年限一人承担算法至销售全链条，资源与责任不匹配 |
| J4 真实准入 | 个人证据如何对应原JD？哪些是已满足、可补、待招聘方确认或明确不符？ | 虚构年限、把校招当社招、把会Python当懂电气／工艺／临床 |
| J5 个人回报 | 固定与浮动收入、工时待命、出差、用工主体与成长是否值得？ | 已证实超出本人约束；用公司盈利替代个人收入与时间回报 |

## 分阶段取证与输出

| 阶段 | 本阶段必须核实 | 可以留到后续的内容 |
|---|---|---|
| 发现与初筛 | 行业／集群归属、公司真实业务、**原帖在招且可投递**、原JD来源与职责、可查的准入条件、明确排除项 | 内部预算、准确工时、薪酬结构、到岗节点；未知须列明，不能当已满足 |
| shortlist 争取名单 | **在招且可投的有效完整原JD**；硬条件逐项核对且无已证实不可跨越冲突；客户与业务、细分领先地位及赚钱能力有适用证据；无已证实硬伤 | 招聘沟通才能取得的C5、J3、J5信息可列为面试核验项，不因未知一律挡在名单外；关键商业事实或身份适配缺失仍clarify |
| 面试与offer决策 | 补核团队资源、当前名额、实际内容、薪酬工时和劳动主体，比较本人回报与可迁移积累 | 关键约束仍不清则不能认定适合接受；offer、接受和离职分别判断 |

- **pending：** 尚未完成初筛。
- **clarify：** 阻碍当前阶段判断的缺口，写明最小补证、来源和下一动作；不把缺公开信息写成公司失败。
- **exclude：** 已证实命中个人排除、商业硬伤或岗位不符，注明原因及证据。
- **shortlist：** 值得准备和争取，明确待面试核验项；不等于已适合入职或自动获得外发授权。
- **在招/可投（前置）：** 先核原帖是否在招、是否有投递入口、最近更新时间；仅转载或完整JD需登录记 clarify，已关闭记 exclude。岗位卡记 `jd_status`/`jd_source`，shortlist 须 `jd_status=在招可投`。

当前有效招聘是岗位进入shortlist的必要条件；**急招改为排序因素，不再一票否决优质在招岗位。** U0表示紧迫度未证实，U1表示有日期且仍有效的招聘方急招声明，U2表示有HC／到岗或流程节点的进一步证据。急招可能来自增长，也可能来自高流失与救火，不能抵消质量问题。

每个机会沿原APP-ID留证据：细分市场／集群／劳动主体与团队／客户和价值位置／领先证据／经营质量／原JD及日期／C与J结论／准入映射／U等级／已知回报／本阶段阻塞项／面试核验项／下一行动。事实、推断和未知分开；不得用任意加权总分抵消硬伤。

## 执行和停止

宏观证据足够定方向后进入公司与岗位验证，不为等待全部条件公开而无限研究。检索由已确认范围驱动，重复来源只算一次；没有新增证据就停止对应问题，换已确认的可行动单元。阶段产出是可复查机会与明确决策，最终结果看合适offer及实际工作条件，不以报告数、搜索次数或投递数冒充转型成功。

脚本管理范围、查询、去重、版本、队列和台账；研究执行者判断业务与岗位。当前框架尚不自动判断公司领先或盈利。历史候选不批量改判，重新评估时记录本规则版本与新证据。外发沿当前授权执行。

早期海外软件样本和修改前规则保留于本地历史快照（见个人项目 规则\AI时代公司与岗位过滤器.md），不再作为现行筛选步骤重复阅读。

## 护城河分级（S/A/B/C/伪）

把"不允许"护城河拆成可判定的五级，用于给每个主体定级并决定投入顺序。**定级必须有可核证据（官方文件／牌照／国务院或部委公告／企业年报／交易所披露）；无证据记「待核」，不得凭印象升级。**

| 级别 | 定义 | 可核识别信号 | 典型 |
|---|---|---|---|
| **S 行政垄断** | 法律或行政法规授予的独家经营，无替代主体 | 专卖专营法规、唯一法定机构、国务院批复 | 烟草专卖、国铁客运、央行清算、盐业专营 |
| **A 特许经营／区域独家** | 政府授权区域独家，价格受管制、回报被核定 | 特许经营协议、输配电价核定文件、独家管网／水气经营权 | 国家电网、南方电网、城市燃气水务、油气管网 |
| **B 规则／通道** | 制定行业规则，或占据结算／交易必经节点 | 国标／行标起草单位、交易中心、清算机构、算力调度平台 | 电力交易中心、数据交易所、标准院、清算所 |
| **C 资源／数据／信任** | 独占资源产权，或垄断信任背书 | 矿业权／探矿权、频谱／轨道、征信库、等保／密评／测评资质、大模型评测资质 | 三桶油上游、稀土、征信中心、测评与认证机构 |
| **伪** | 六层全缺，靠挂靠集团名或人力套利 | 无自研核心、无独家数据、无结算权；驻场／外包／集成 | 各类 IT 外包与人力资源公司、挂靠央企名的地方集成商 |

**判定纪律**：
1. 单一客户依赖不等于护城河；集团有牌照不等于目标用工主体有，须判定「实际签约主体 → 母公司 → 牌照持有方」三层关系。
2. 拿到 S/A 级证据方可进「强护城河名单」；B/C 级进「次级名单」；伪级一票排除，不占 shortlist 名额。
3. 母公司 S/A 级、但目标子公司是外包壳的，按子公司定级（多数降为伪）。
4. 牌照护城河只保证「企业不死」，不保证「个人值钱」；定级后仍要过回报（J5）与可迁移性（J2）检查。

## 岗位降级规则

默认检索三类岗位，按优先级：**Agent 应用开发 > 测试开发 > 测试**。

降级条件（从严到宽）：
- **S/A 级主体**：允许检索范围下探到「测试工程师」等常规测试岗——护城河足够强、平台足够稳，岗位内容可入职后再向 Agent／自动化方向迁移。
- **B/C 级主体**：只检索 Agent 开发与测试开发岗；常规测试岗不进候选。
- **伪级主体**：任何岗位都不进候选。

降级不等于降标准：真实职责（J1）、学历年限准入（J4）、回报与用工主体（J5）照旧核；降级只放宽「岗位名称与职责范围」。

优先 vs 排除：
- 优先：母公司护城河为「数据／流程型」（电网／石油／银行／政务），且数科子公司真自研核心系统（有数据独占），且个人可进入评测／认证与数据场景的交叉岗（AI／Agent 评测、数据场景自研）。
- 排除：母公司纯「牌照／特许型」且无数据价值（烟草／水务／铁路客运）；或「集成／外包管理」壳（JD 全是交付／供应商管理／驻场，无自研、无数据独占）。

## 大厂外包专条（默认判死）

为大厂承接人力、驻场、项目制交付的公司（如新凯来之于华为系、外企德科之于多家大厂）**一律定伪、直接排除**。理由不是能力问题，而是这类主体**没有护城河**：商业模式是用低价采购劳动力、同时规避用工法律责任。**默认不去**，不因岗位名称含 AI／测试而放行。

## 投递执行默认策略（安全默认）

**筛选范围扩大不等于投递权限扩大。** 本仓库默认 dry-run：

- **外包／派遣岗**：可在取得使用者明确授权后真实投递，用于跑通链路、收集真实 HR 沟通反馈。
- **正编岗**：默认**只登记、不真实投递**；由使用者本人决定何时开启全量投递。
- 投递留回执（平台、时间、简历版本哈希）；结果未知先对账不重投；登录与验证码由使用者本人处理。

## 学历与年限门槛的处理

**学历（硕士／博士）与工作年限（3／5／8 年）默认不作为排除理由。** 社招实际对学历与年限常有弹性，应届与短经验者应扩大而不是缩小检索面。

处理方式：
- 岗位写「硕士及以上」或「3-5 年／5-10 年」→ **列入查找范围并进入投递候选**，在台账标 `degree_risk` / `years_risk`，写明差距年限。
- 排除只基于**真正的硬约束**：专业资质（如注册核安全工程师）、执业资格、涉密政审、身份（应届／社招）、城市迁居、行业下行、外包属性。
- **能力不匹配仍是风险，但不作为自动排除理由**：标 `skill_gap` 后仍可投，由使用者决定是否投入准备。

## 国资控股上市公司的准入约束

不因「国资控股」四个字放行。这类公司里大量是**纯市场化竞争的国企**，没有真护城河，处境与普通民企无本质差别。必须同时满足两条才进入候选：

1. **有真护城河**：按 S/A/B/C 分级能落到具体证据（牌照、特许经营、区域独家、结算节点、资源产权、信任背书）。
2. **所在行业非下行**：不取高度绑定房地产、传统建筑等下行链条的主体。

只有「国资控股」而不满足上述两条的，按「伪／无护城河」处理——**换壳不换命，不算改善**。

例外：外包服务商内部明确挂「自研产品团队」的岗位，需有自研产品、核心代码、数据独占证据；集团自有数科公司（自己人）与外部服务商（供应商）不能混。命中排除时，排除理由固定写「外包／驻场、无护城河」，不再消耗 shortlist 名额。
