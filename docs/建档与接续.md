# 建档与接续

这是 AI 助手首次接手和换会话时的工作顺序。代码负责初始化和本地状态，对话助手负责理解、调研和判断。任何能够读取本地文件的助手均可按此执行；没有助手时也能按模板手动工作。

## 初始化

在仓库根执行 `python -X utf8 scripts/setup.py`。它只创建缺失文件，保留已有档案和台账。读取输出的 workspace 和 manifest，后续路径以 manifest 所在目录为实例根。运行 `python -X utf8 scripts/onboard.py status` 查看尚缺哪些条件，输出不显示个人字段值。

默认实例与仓库同目录，内容线、笔面线、memory、`.local`、`data` 均被 Git 忽略。行业与投递直接使用通用方法、实例配置和台账，不初始化空壳目录。实例位置由配置决定。所有布局均使用同一套 [工作闭环](工作闭环.md)，不维护专属旧流程。

同机另一个使用者先运行 `python -X utf8 scripts/setup.py --workspace <空目录>`，然后为后续命令设置 `OFFERLOOP_LOCAL=<该目录>/offerloop.local.json`。PowerShell 用 `$env:OFFERLOOP_LOCAL='绝对配置路径'`，POSIX shell 用 `export OFFERLOOP_LOCAL='绝对配置路径'`。不要在旧用户档案上改名覆盖。

## 对话建档

先复用用户本轮已提供的信息和经授权的现有简历。每轮只问一至三项会改变下一步的缺失条件，不让用户填写整张表，不要求先报手机号、证件或精确工资。

1. 当前想解决什么、最高学历/专业及毕业时间、目前在读/就业/离职状态。只有资格判断需要时再问正式就业、实习、社保和合同情况，未知保留 `null`。
2. 期望地区、可接受的工作方式与硬性限制、希望探索的方向。方向不确定也是有效输入，不替用户自动选择 Agent 或其他默认职业。
3. 已做过的工作或项目、本人职责、可解释的技术与成果。接受“暂无项目/尚未评估”，按当前任务补一个能用于判断的例子即可开始。

将明确陈述更新到同一个 `personal/投递数据.json`。education 记录教育，work_experience 每段注明 `kind=internship/formal/other`；career_preferences 记录意向与约束；eligibility 记录资格事实；capabilities 记录技能和项目证据。个人事实只维护这一份，简历按需表达且不得改变事实。新信息覆盖旧结论时先保留仍未解决的冲突。

使用 `scripts/onboard.py apply --json -` 从 stdin 写入 `{ "source": "本轮用户陈述", "updates": { ... } }`。也可读私有 JSON 文件，使用后删除可重建输入。顶层对象递归合并、数组整体替换；提供数组时须带上仍有效的旧条目。命令只写本地档案，不确认检索范围或启动外发。旧平台用的 facts 字段保留，不把建档命令当在线简历映射器。

无需为了写已明确陈述的事实再次确认。对影响取舍的推断或新推荐，在对话中让用户澄清；未回答项不能因等待而视为同意。

## 从档案进入工作

| 用户当前问题 | 读取入口 | 本轮完成标准 |
| --- | --- | --- |
| 不知投什么 | 当前状态 + 岗位筛选规则 + 企业背调方法 | 根据真实需求与个人条件给主投、并行、暂缓及改判条件 |
| 已有目标岗位 | 内容线 README + 材料与训练 | 原 JD 对照已有证据，形成可用材料和少量优先补齐项 |
| 即将笔试面试 | 笔面线 README + 材料与训练 | 练题、保留原回答、明确缺口及异题复验 |
| 跟进申请 | 当前状态 + 执行手册 + 实例执行配置 | 有回执才记已投，更新下一动作，区分资格、材料、技术反馈 |

方向未知时允许先探索真实 JD。研究不是先填好行业再搜索。只有结构化执行线要用检索单元时，才将用户已接受的范围写入实例配置目录的当前检索范围.json（默认 .local/config/），每格包含 `id/industry_id/industry/city/role_terms`。`status=confirmed` 和 confirmation_reference 必须有真实对话依据。未讨论时保留 draft，研究和材料准备仍可进行。`external_actions_enabled` 保持 false。

有足够信息后立即推进一个真实任务，不等所有字段齐全或学习完。联网能力缺失时先完成个人证据盘点和材料准备，市场需求标为待核。不能用虚构测试样本冒充现招岗位。

## 接续与换设备

实例 memory/workspace.json 维护现行决定、材料状态、待确认条件和下一步，CURRENT_STATE.md 由脚本结合台账生成。每次开始 refresh，每次工作后 close，详见 [工作闭环](工作闭环.md)。岗位与操作回执留台账，训练原文留本地，飞书按授权承接进度、跟进和复盘。

新会话按 AGENTS → memory → 对应线 README 恢复，无需旧对话。换设备先拉取仓库，再通过私有渠道恢复 manifest、.local、四条线、memory 和 data，保持相对布局；SQLite 用一致性备份或停写后复制。仅拉取 Git 会得到空白框架，不能恢复被忽略的个人资料。浏览器和飞书重新认证。

profile.py 是旧平台专用字段映射工具，目前有“两段工作、一段项目”的格式限制，首次建档不调用它。非技术岗位也可用四条线方法与材料模板，不要求适配招聘网站自动表单。
