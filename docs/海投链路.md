# 海投链路（发现 → 筛选 → 海投）

2026-10-30。主链路已收敛为固定入口 `scripts/chain.py`，V4-flash 只需按 `chain.py <步骤>` 顺序执行，无需理解各脚本参数。全部默认 dry-run；真实投递仅外包岗（某外包派遣公司/某OD外包岗），正编与「在考虑范围」岗只登记不投。

## 1. 主链路总览

```
发现(discover) → 入库(import) → 筛选(screen) → 投递清单(ready) → 海投外包岗(apply)
   browser_cdp     boss_discover   company_check     ready_list      harness.py apply
   jobs → jobs.json   → APP-###       + job_check        → 投递清单.md    (dry-run)
                                       C1-C5 / J1-J5
```

- `discover/import/screen/ready/apply` 五步可单跑；`run` 一次串起（全 dry-run）。
- 每一步 `chain.py <步骤>` 内部调既有脚本，步骤间靠文件/台账传递结果。

## 2. 每步固定命令

统一工作目录为项目根 `Personal_log`。chain 中间产物落在 `data/chain/`。

| 步骤 | chain.py 固定命令 | 底层等价命令 | 产出 |
|---|---|---|---|
| 发现 | `python -X utf8 scripts/chain.py discover --platform boss`（或 `zhaopin`） | `node scripts/browser_cdp.js --platform boss jobs > jobs.json` | `.local/offerloop/chain/jobs.json` |
| 入库 | `python -X utf8 scripts/chain.py import`（dry-run 只打印）；加 `--apply` 真入库 | `python -X utf8 scripts/boss_discover.py --jobs-json jobs.json [--apply]` | 台账 `jobs` 表 APP-### 记录（`--apply` 时） |
| 筛选 | `python -X utf8 scripts/chain.py screen` | `company_check.py init --company <公司>` + `job_check.py init --job <公司-岗位>`（每岗） | `.local/offerloop/chain/证据卡/<APP-xxx>/company_card.json` 与 `job_card.json` |
| 投递清单 | `python -X utf8 scripts/chain.py ready --scope ready`（或 `shortlist` / `all`） | `python -X utf8 scripts/ready_list.py --scope ready` | `投递线/投递清单.md` |
| 海投外包岗 | `python -X utf8 scripts/chain.py apply`（plan，只列命令）；加 `--execute` 才调 `harness.py apply`（仍 dry-run，不 send） | `python -X utf8 scripts/harness.py apply <平台> <岗位ID>` | 外包岗投递命令列表（dry-run）；正编/在考虑范围打印「登记不投」 |
| 一键串起 | `python -X utf8 scripts/chain.py run` | 依次 discover→import(dry)→screen→ready→apply(plan) | 同上，全非破坏性 |

### 投递闭环（2026-10-31 新增：check→prepare→submit→followup）

| 步骤 | chain.py 固定命令 | 作用 | 产出 |
|---|---|---|---|
| 筛选校验 | `chain.py check` | 校验已填 C1–C5/J1–J5 证据卡，列出可 shortlist 岗位与缺口 | `.local/offerloop/chain/证据卡/<APP>/` 的校验结果 |
| 投递准备 | `chain.py prepare <APP-xxx> --resume <pdf>` | shortlist 岗 + 简历 → `applications.stage=ready`（chain 简化路径，不强制 research_scope） | applications 记录 + resume_hash |
| 投递执行 | `chain.py submit`（dry-run 只列命令）/ `--execute` | 外包岗打开详情→定位「立即投递」→点击→抓回执（url/文本/成功标记/截图）→record(submitted) | 回执 + 台账 submitted |
| 跟进 | `chain.py followup [--mail] [--draft APP-xxx]` | 列活跃申请；拉邮箱分类；生成跟进草稿 | 活跃申请清单 / 草稿 |

- `submit` 默认 dry-run，只定位投递按钮不点击；`--execute` 才真实点击（仅外包岗，且 授权后才启用）。
- 回执抓取用 `browser_cdp.js submit`（`--execute` 时经 `harness.py apply --execute` 调用），成功标记命中才记 submitted；出现确认弹窗记 `confirm_dialog`，不自动二次点击。
- `prepare` 是 chain 简化路径（`pipeline.chain_prepare`），只要求 shortlist + 简历文件；严格 research 路径仍走 `pipeline.py prepare`。

### 各步前置与后置

1. **discover 前置**：宿主机运行 `scripts/browser_launch.cmd` 起 Chrome（`--remote-debugging-port=9222`），且已登录标签停留在目标平台搜索结果页；脚本读当前标签 DOM，不新建标签（避免重过 BOSS 安全验证）。
2. **screen 后置**：证据卡是空模板（judgment/evidence 待填），Agent 逐项填 C1–C5 / J1–J5 后 `company_check.py validate --card ...`、`job_check.py validate --card ...` 校验；结论 `shortlist` 再走 `pipeline.py prepare`（逐岗简历）+ `track`（登记平台/入口/话术）。
3. **ready 前置**：默认 `--scope ready` 只显示 `stage='ready'` 的 `applications`；纯 `boss_discover` 入库是 `decision='pending'`，未 prepare 时 ready 清单为空。先用 `--scope shortlist` / `all` 看已筛候选。
4. **apply 前置**：`ready` 岗需在 `pipeline.py track` 里登记 `platform`（boss/zhaopin/meituan），否则 chain 标「平台待登记」并跳过。

## 3. 外包岗判定规则（哪类算外包可投）

- **可真实投递/打招呼测试 = 外包岗**：某外包派遣公司（含「某外包派遣公司数字」等）与某OD外包岗。
- **只登记不投 = 正编 + 在考虑范围岗**：其余全部。
- 实现（`config.py` 的 `OUTSOURCING_MARKERS`，`chain.py` 引用）：对岗位 `company/title/summary/next_action` 做小写子串匹配，默认命中「外包 / 派遣 / 劳务 / od / od外包」等通用关键词，具体目标公司经本地配置覆盖后即判外包。
- 这是**启发式**，最终以实际劳动主体核验为准；dry-run 下误判仅多列一条测试命令，不产生真实投递，风险低。判定见 `config.py` 常量，改判据改这一处即可。

## 4. 关键接口（读源码核实）

### browser_cdp.js jobs 输出格式
`node browser_cdp.js --platform boss|zhaopin jobs` 打印一个 JSON 数组，每项：

```json
{"title":"岗位名","company":"公司名","city":"杭州|深圳|…","years":"1-3年|应届生|…",
 "education":"本科|硕士|…","source_url":"https://…","source_level":"partial",
 "observed_on":"YYYY-MM-DD","summary":"卡片文本前160字","next_action":"打开详情页核验原JD与准入"}
```

- 依赖 `platforms.json` 的选择器（boss 用 `a.job-name` 锚点、`.boss-info` 公司；zhaopin 用 `.job-card`、公司名锚点）。
- 需要浏览器 CDP 在线（`127.0.0.1:9222`）；`search` 子命令只打印 URL，不导航，需手动停在结果页。

### boss_discover.py 参数
`python -X utf8 boss_discover.py --jobs-json <file> [--apply] [--db <path>]`

- 默认 dry-run：打印 `APP-###` 记录 + `# 共 N 条（dry-run，未入库）`。
- `--apply` 入库到台账（沿 `source_url` 去重，`APP` 序号取台账最大号+1）。
- 映射字段：`id/company/title/city/source_url/source_level/observed_on/summary/next_action`；**丢弃** jobs 里的 `years/education`，且**不写 `research_scope`**（因此不满足 `pipeline.eligible`，走本 chain 的简化筛选路径，不直接进 `prepare`）。

### ready_list.py 输出
`python -X utf8 ready_list.py [--scope ready|shortlist|all] [--output 路径]`

- 默认写 `投递线/投递清单.md`，并打印 `{"output","count","scope","external_send":false}`。
- `ready`=待投递（`applications.stage='ready'`）；`shortlist`=初筛候选（`decision='shortlist'`）；`all`=全部。
- 清单每岗含：投递入口、逐岗简历（SHA256）、筛选结论+依据、打招呼/准备卡、下一行动。**不发送任何内容**，最后点击由本人完成。

### harness.py apply
`python -X utf8 harness.py apply <平台> <岗位ID>`

- 平台：boss/zhaopin（`browser_cdp.js --platform <p> apply`，选择器已配）、meituan（`click 投递`）。
- **默认 dry-run**：只定位投递按钮，不点击；`browser_cdp.js apply` 带 `send` 才真实外发，`harness.py` 不传 `send`。
- 已知缺口：`harness.py apply` 目前**接受但未使用 `job_id`**，也未带 `--url/--tab`，故 `browser_cdp.js apply` 会要求 `--url <exact URL>` 或 `--tab <ID>`；真正按岗位投递需先在 harness.py 里把 `job_id → 投递 URL` 接上（不在 chain.py 范围）。

## 5. 边界（harness.json boundary）

- **sensitive_skip**：身份证号、护照、人脸识别、生物识别 —— 不采集不填写。
- **human_reserved**：登录、验证码、新协议、接受 offer、离职、迁居 —— 由本人处理。
- **real_apply**：真实投递/打招呼仅外包岗（某外包派遣公司/某OD外包岗）；正编与在考虑范围岗只登记不真投。
